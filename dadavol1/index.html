01 · why

the intern has root

the threat model changed. it is not only “did i click a bad link.”

you point an agent at a folder. it reads issues, READMEs, web pages, and your own notes. it writes files. it runs commands. it can install packages. a hostile sentence hiding in any of those places can become a command on your machine. one person. no security team. the blast radius is the whole laptop unless you cut it down.

what it is

defensive hardening. how to keep secrets out of prompts, keep the agent inside one project, and make the diff the lock on every write. study hostile mechanics only to invert them into barriers.

what it is not

not a pentest course. not exploit recipes. not permission to touch a machine you do not own. tools of creation, not violence. air-gapped run is a right.

02 · iron

the iron fences

  • white hat only. no exploits. no attacking systems. no malware. no payload delivery. hostile artifacts are text to study, never something you run.
  • no enclosure. never rent-trap user bits. the machine belongs to the person who bought it. software that withholds your own files is hostile.
  • air-gapped right. local intelligence must be able to run with the network off. no phone-home required to think.
  • inversion. learn the mechanic of the attack so the defense is exact. curiosity without a fence is how people become the problem they were studying.

03 · inversion

the solo-dev inversion matrix

each row is a thing that actually happens to people shipping with agents. the right column is the barrier.

dark art

indirect prompt injection

mechanic

untrusted text in a file, ticket, web page, or pdf tells the agent to ignore you and leak keys or run a command.

defense

retrieved text is data, never instructions. your rules file is the only voice that binds the agent. isolate untrusted sources into their own session.

dark art

secret harvest

mechanic

.env files, ssh keys, tokens, wallet seeds, and session cookies get pulled into context, then into a vendor log, a commit, or a paste.

defense

secrets live in env or a local secrets dir. never in chat. never in git. deny-list .env, .ssh, id_rsa, tokens, wallets. rotate anything that touched a prompt.

dark art

confused deputy

mechanic

the agent has your shell, your editor, and your logged-in git. it will do what the last loud instruction said, including one that was not yours.

defense

workspace root is the blast radius. open the project, not the home folder. least privilege on tools. auto-run off. you approve shell and writes.

dark art

supply chain via the agent

mechanic

the agent adds a package, a github action, or a build script. a typosquat or a postinstall hook runs as you.

defense

read lockfile diffs like they are code. pin versions. audit. no network during builds when you can. never let a build script hit the open internet as a side effect of “just install it.”

dark art

destructive shell

mechanic

rm, format, git push --force, chmod on the wrong tree, migrate production. one confident command, no undo.

defense

human gate on destructive verbs. the diff is the lock. production credentials do not live on the agent machine. backups you have restored once are the only backups.

dark art

malicious connector

mechanic

a third-party mcp or plugin runs with your tokens. it can read mail, drive, git, or the repo, and send it out.

defense

one job, one connector. token in env, never in git, never in chat. read-only until you need write. delete the ones you do not use.

dark art

code leaving the box

mechanic

cloud models see whatever you put in the thread. private repos, customer data, unpublished work, all of it becomes someone else’s log.

defense

know what left the machine. local models for private work. strip secrets before any remote call. air-gap is a right, not a luxury setting.

dark art

instruction smuggling

mechanic

a README, a comment, or a “fix this ci” issue contains a hidden system prompt. the agent treats it as law.

defense

your standing rules bind the agent. untrusted markdown is data. if a file starts giving orders, stop and read it as an attack, not as help.

04 · depth

five rings of defense

no single layer carries the whole posture. if userland falls, the workspace still holds. if the workspace is probed, the network and the keys contain the blast.

0 secrets

  • one home for secrets: env files or a local secrets dir. not the repo. not the chat.
  • gitignore .env, *.pem, *.key, id_rsa, tokens, wallets, .npmrc with auth.
  • agent deny-list those names. if a tool can read them, it will.
  • production credentials do not live on the laptop that runs the agent.
  • anything that entered a prompt is burned. rotate it.

1 workspace

  • open the project folder. never the user profile, never the disk root.
  • that folder is the blast radius. name it. keep it small.
  • separate clones for untrusted work. do not mix a random gist into the company tree.
  • human-only material does not exist to the agent. no path, no tool, no lookup.

2 human gate

  • auto-run off. yolo mode is the hole.
  • you read the diff before apply. the diff is the lock.
  • shell, network, and package installs are confirmations, not background noise.
  • destructive verbs wait: rm, format, force-push, migrate, chmod, deploy.
  • the agent does not grade its own homework. tests and a second look do.

3 network

  • local servers bind 127.0.0.1. not 0.0.0.0 unless you meant the room to hear it.
  • default-deny inbound. you did not open a port by accident.
  • connectors are egress. each one is a pipe out. cut the ones you are not using.
  • know which model is remote. a “local” ui that still ships the prompt is not local.

4 machine

  • full-disk encryption. screen lock. os updates that you actually install.
  • github: 2fa, hardware key if you have one, least-privilege tokens, no classic pats in the repo.
  • linux: kernel is the arbiter. user-mode hooks are convenience, not a security boundary.
  • windows: the agent’s workspace is not c:\. credential manager, not a plaintext dump.
  • local models exist so private work can stay on the box.

05 · this afternoon

do this today

  1. turn auto-run off the agent waits. you say yes. that single switch is most of the job.
  2. open one project folder not the home directory. the path you opened is the blast radius.
  3. gitignore the secrets .env, keys, tokens, wallets. then search git history once so yesterday’s leak is not still in the log.
  4. deny-list those files in the agent gitignore stops commits. deny-list stops the intern from reading them into a prompt.
  5. arm 2fa on github the agent can push. a stolen session without a second factor is a stolen origin.
  6. bind local servers to loopback 127.0.0.1. check with the inspect commands below. if the world can hit it, it is not local.
  7. cut unused connectors every mcp and plugin is another process with a token. if you have not used it this week, it goes.
  8. read one lockfile diff as if it were code that is where the agent hides a new dependency. if you cannot name why it was added, revert it.

06 · see

inspection

look. dirt hides failure. these are defensive checks on your own machine.

windows

# who is listening
netstat -ano | findstr LISTENING

# is this process bound to the world
netstat -ano | findstr ":3000 :8080 :5173"

# firewall profiles
Get-NetFirewallProfile | Format-Table Name, Enabled

# what the agent might still see
git ls-files -o --exclude-standard
git check-ignore -v .env

linux

# who is listening
ss -tulpn

# packet filter
nft list ruleset

# kernel posture
sysctl kernel.kptr_restrict kernel.dmesg_restrict kernel.unprivileged_bpf_disabled kernel.yama.ptrace_scope kernel.randomize_va_space

# scratchpads must not execute
mount | grep -E '/tmp|/dev/shm'

# setuid surface
find /usr /bin /sbin -perm -4000 -type f 2>/dev/null

every os · git and secrets

# did a secret already land in history
git log -p --all -S "SECRET" -- .env
git grep -n -E "AKIA|ghp_|sk-|xox.|BEGIN OPENSSH" -- . ':!.git'

# lockfile the agent just touched
git diff -- package-lock.json pnpm-lock.yaml Cargo.lock go.sum

# remote vs local
git remote -v

linux kernel values worth holding: kptr_restrict=2 · dmesg_restrict=1 · unprivileged_bpf_disabled=1 · yama.ptrace_scope=2 · randomize_va_space=2. /tmp and /dev/shm: noexec, nosuid, nodev.

07 · standing

standing laws

  • assume userland is compromised. do not base trust on a helper hook, an editor plugin, or a “safe” autocomplete. the kernel, the os account, and the keys you did not paste are the real boundary.
  • verify before executing. probe the environment. read the command. never guess.
  • minimal attack surface. cut unused services, unused connectors, unused tokens. extra weight is not kindness.
  • defense in depth. secrets, workspace, human gate, network, machine. if one ring fails, the next still holds.
  • the diff is the lock. unreviewed apply is how a poisoned instruction becomes production.
  • empty well, say so. do not invent a cite. do not ship a stub that claims done.

5s on the box

cut dead tokens and dead plugins. place secrets in one living home. see the listeners, the diff, the lockfile. hold the deny-list and the auto-run switch so tomorrow’s hand does not guess. become a shop that does not need a watcher.
